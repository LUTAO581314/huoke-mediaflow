# 安装与复现（从零到出第一条片）

目标：在一台**干净的 Mac** 上，把这个仓库跑起来，做到 `mf health` 全绿，然后剪出一条 30 秒测试片。

> 这套东西不是「装一个软件」，而是**三个东西拼起来**：
> 1. **`mf`**（本仓库的 Python 单文件 CLI，只管预处理/质检/导出/片卡）
> 2. **D剪 引擎**（上游开源项目 + 本仓库两个补丁，管时间线/字幕/渲染，这是核心）
> 3. **DSH**（宿主应用，面板和 `djian_*` 工具由它提供）
>
> 前两个都要装，缺一个面板里就没有剪辑能力。

---

## 第 0 步 · 先体检，别装东西（AI 助手务必从这里开始）

```bash
bash scripts/check-env.sh          # 人看
bash scripts/check-env.sh --json   # AI 解析：{"ok","fail","issues","next"}
```

**只补 `next` 里列的东西，按顺序补。** 不要跳过体检直接 `brew install` / `npm install` / `pip install`。

缺的是 Mac 侧工具时，可以直接跑半自动脚本（每步会问；`--yes` 全自动；**只装 Mac 工具，不装模型**）：

```bash
bash scripts/bootstrap.sh          # 逐项确认
bash scripts/bootstrap.sh --yes    # 全部同意
```

第 3 步（DSH 里 link `@djian/*`）脚本不代劳——要改 profile 的 `package.json`，见下文。

### 绝对不要在这台 Mac 上装这些

| 不要装 / 不要跑 | 它该在哪 | 为什么 |
|---|---|---|
| `ollama`、任何大模型权重 | Windows `C:\mediagpu`（ssh `l-l`） | Mac 跑不动 14B 模型，白下几十 GB |
| `faster-whisper` / `whisper.cpp` / `openai-whisper` | 同上 | Mac 无 CUDA，CPU 转录慢到不可用（日志会打 `FP16 is not supported on CPU`） |
| `GPT-SoVITS` / TTS 模型 | 同上 | 需要 GPU |
| `torch` / CUDA 包 | 同上 | `mf.py` 只用标准库 |
| 示例素材、测试视频包 | 不需要 | 用自己的素材 |

**`mf asr / translate / tts / sep / sovits` 本身就是远程命令**，本机不装任何模型也能调用——前提是 Windows 从机在跑。

> AI 助手的完整铁律见仓库根的 [`AGENTS.md`](../AGENTS.md)。

## 0. 先确认你要复现什么

| 你想做的事 | 需要装到哪一步 |
|---|---|
| 只跑规则检查、合规拦截、模板出片卡 | 第 1、2 步（`mf` + ffmpeg） |

| 说话类视频要识别/翻译/配音 | 再加第 6 步（Windows GPU，可选但强烈建议） |

## 3. 安装步骤

### 第 0 步 · 拉代码并摆好目录

目录约定（后面所有命令都依赖它）：

```
~/获客平台/仓库/huoke-mediaflow      # 本仓库
~/mediaflow/                        # 工作目录（mf.py 软链、工具、D剪 引擎都在这）
~/媒体库/                            # 素材库（工程、成品）
~/获客平台/知识库/剪辑规范.md         # 唯一规则源
```

```bash
mkdir -p ~/获客平台/仓库 ~/mediaflow ~/媒体库 ~/获客平台/知识库
gh repo clone LUTAO581314/huoke-mediaflow ~/获客平台/仓库/huoke-mediaflow
```
> 仓库是私有的，需要先被邀请为协作者。

### 第 1 步 · 基础二进制

```bash
# ffmpeg 必须能被 PATH 找到（mf 只认 PATH）
ffmpeg -version | head -1     # 期望 9.x 或 8.x
ffprobe -version | head -1
yt-dlp --version

# 没有就装
brew install ffmpeg yt-dlp node uv
node -v    # 必须 >= 22.18
```

### 第 2 步 · D剪 上游 + 两个补丁（**最容易漏的一步**）

```bash
git clone https://github.com/Loliyer520/DSHL-DeepPack-Jian.git ~/mediaflow/djian
cd ~/mediaflow/djian
git checkout e1b6130          # 2.1.3，补丁就是按这个版本做的

# 本仓库的两个补丁
git apply ~/获客平台/仓库/huoke-mediaflow/engine/patches/djian-session-binding.patch
git apply ~/获客平台/仓库/huoke-mediaflow/engine/patches/djian-desktop-shell.patch

# 装引擎依赖（Remotion 4.0.526 会一起装上）
npm install
```

两个补丁分别治什么：

| 补丁 | 治的问题 |
|---|---|
| `djian-session-binding.patch` | 每个新会话自动多建一个空项目；加「同名空项目复用」和显式 `bindSessionTo` |
| `djian-desktop-shell.patch` | 桌面端渲染页是 `dsh-app://` 协议（不是 http），放开 origin 白名单 |

> 上游升级到 3.0 后 `client-timeline` 变了，`djian-desktop-shell.patch` 可能失配 —— 那时先跑 CI 的漂移探测看红在哪，再重新 diff。

### 第 3 步 · 把 D剪 装进 DSH（**之前完全没文档的一步**）

`@djian/*` 六个包**不在 npm 上**，必须用本地 `link:` 挂进 DSH profile。

1）编辑 `~/.dsh/profiles/desktop/package.json`，在 `dependencies` 里加（**必须是绝对路径，`~` 不会被展开**）：

```json
"@djian/client-ui-library":  "link:/Users/<你>/mediaflow/djian/packages/client-library",
"@djian/client-ui-timeline": "link:/Users/<你>/mediaflow/djian/packages/client-timeline",
"@djian/dsh-bundle":         "link:/Users/<你>/mediaflow/djian/packages/dsh-bundle",
"@djian/engine":             "link:/Users/<你>/mediaflow/djian/packages/engine",
"@djian/host-bridge":        "link:/Users/<你>/mediaflow/djian/packages/host-bridge",
"@djian/webui":              "link:/Users/<你>/mediaflow/djian/packages/webui"
```

2）在 profile 目录装一遍：

```bash
cd ~/.dsh/profiles/desktop && npm install
ls node_modules/@djian/      # 应看到 6 个目录
```

3）把面板/预设注册进 `~/.dsh/profiles/desktop/cordis.patch.yml`：

- 内容取自本仓库 `djian-bundle/cordis.patch.yml`（含「获客项目先读剪辑规范」的人设），
- 或直接用上游 `~/mediaflow/djian/packages/dsh-bundle/cordis.patch.yml`（无人设版）。

它做了三件事：注册时间线 UI / 素材库 UI、注册 host-bridge 并在 **5180** 端口按需拉起引擎、注册一个叫 **「D剪 视频剪辑」** 的预设。

4）重启 DSH，侧栏里应该出现「D剪 视频剪辑」预设；进入后右侧出现剪辑面板。

### 第 4 步 · Multiplane（片头卡/参数卡/封面）

```bash
mkdir -p ~/mediaflow/tools/multiplane && cd ~/mediaflow/tools/multiplane
npm init -y
npm install multiplane@0.3.13 --legacy-peer-deps   # three.js 的 peer 依赖要放宽
npx playwright install chromium                     # 无头渲染要用 Chromium
npx multiplane doctor                               # 全绿才算好
```

### 第 5 步 · crv（拆片看片，可选）


### 第 6 步 · `mf` 装好并挂上规则

```bash

cp ~/获客平台/仓库/huoke-mediaflow/docs/剪辑规范.md ~/获客平台/知识库/剪辑规范.md

# PATH 里的 mf

#!/usr/bin/env bash
exec "$HOME/mediaflow/.venv/bin/python" "$HOME/mediaflow/mf.py" "$@"
```

### 第 7 步 · Windows GPU 从机（可选）

只有识别/翻译/配音/分离需要。


## 4. 路径假设与环境变量

代码里所有路径都能覆盖，别人机器上不用改代码：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `MF_RULES` | `~/获客平台/知识库/剪辑规范.md` | 规则文件位置 |
| `MF_TOOLS` | `~/mediaflow/tools` | multiplane / crv 所在目录 |
| `MF_SHOTS` | `~/媒体库/素材/模板/multiplane` | 模板生成目录 |
| `DJIAN_API` | `http://127.0.0.1:5180` | D剪 引擎地址 |
| `DSH_SESSION_ID` | 由 DSH 注入 | 会话 ↔ D剪 项目绑定 |

`~/媒体库` 和 `~/获客平台` 这两个目录名是写死的（不是环境变量）。如果你的目录不同，改 `mf.py` 顶部的 `LIB` / `ROOT` 常量。

## 5. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| `403 CLIENT_HEADER_REQUIRED` | 直接 curl 引擎，没带 `X-Djian-Client` 头 | 自己写请求要加；`mf` 已自动带 |
| `shot_not_found` | Multiplane 的 shot 路径必须是 `--root` 的相对路径 | 传相对路径，别传绝对路径 |
| `✗ 找不到剪辑规范` | 规则文件不在默认位置 | 设 `MF_RULES` 指向 `docs/剪辑规范.md` |
| 面板里连不上引擎 | 引擎没起 / 端口被占 | `mf dj status` → `mf dj up`；日志 `~/.djian/logs/engine.log` |
| 每开一个新会话就多一个空项目 | 没打 `djian-session-binding.patch` | 打补丁；`mf dj prune --yes` 清历史 |
| `npm install` 报 peer 冲突 | three.js 的 peer 太严 | 加 `--legacy-peer-deps` |
| Node 版本报错 | 引擎要求 ≥22.18 | 升 Node |
| Mac 上转录慢到不可用 | Mac 无 CUDA，whisper 走 CPU（日志 `FP16 is not supported on CPU`） | 用 `mf asr` 走 Windows |
| `ollama 超时` | Windows 上 ollama 没启（禁了自启） | 手动 `C:\mediagpu\bin\ollama-serve.cmd` |
| 导入大文件失败 | D剪 单文件上限 512MB | `mf dj import` 会自动按时间切段 |
| 导出被拦 | 文案命中合规红线 | 看提示改文案；确需强出加 `--force`（会告警） |

## 万一 `~/mediaflow` 没了（恢复步骤）

2026-11-12 真实发生过一次：目录被整块移走/删除，但 D剪 引擎进程还在按已删除的文件跑，表面像"还能用"，重启就废。

**先找备份，别急着重装**（重装要连 GitHub，国内直连常卡死）：

```bash
ls -lh ~/获客平台/归档/ | grep mediaflow     # 找 mediaflow-dirty-*.tar.gz（约 617MB）
tar xzf ~/获客平台/归档/mediaflow-dirty-<日期>.tar.gz -C ~     # 解出 ~/mediaflow，约 1.9G / 15 秒
```

这份归档里已经含 `.venv`、`djian`（含补丁）、`tools/multiplane`、`tools/crv`，解完基本就是原样。

**解完必须重启引擎**（旧进程吃的是已删除的 inode）：

```bash
ps -p "$(python3 -c 'import json,pathlib;print(json.loads((pathlib.Path.home()/".djian/engine-port.json").read_text())["pid"])')" -o pid=,command=
kill <那个 pid>        # 只杀引擎，不要杀 DSH app 主进程
mf dj up
curl -s localhost:5180/api/health      # 期望 {"ok":true,"service":"djian-engine",...}
```

**验收**：`bash scripts/check-env.sh` 要 21 通过 / 0 失败；再跑一遍 `mf new` → `mf dj import` → `mf export`。

**备份习惯**（动 `~/mediaflow` 之前先做）：

```bash
tar czf ~/获客平台/归档/mediaflow-$(date +%Y%m%d).tar.gz -C ~ mediaflow
```

**注意**：`~/.dsh/profiles/desktop/node_modules/@djian/*` 是指向 `~/mediaflow/djian/packages/*` 的软链，
目录一没，6 个软链就全悬空，面板会显示没有剪辑能力——这不是面板坏了。
