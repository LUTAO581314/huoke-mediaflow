# 架构与引擎

这套剪辑环境由**三个进程 + 一堆命令行工具**组成。看懂这张图，就知道为什么"只 clone 仓库跑不起来"。

```
┌───────────────────────── Mac（制作层） ─────────────────────────┐
│                                                                  │
│  DSH 桌面端 ──(面板/工具)──► host-bridge ──spawn──► D剪 引擎 :5180 │
│                                    │                     │        │
│                                    │              Remotion 渲染    │
│                                    ▼                     ▼        │
│                          ~/.djian/projects/<pid>/     成片 mp4     │
│                                                                  │
│  mf CLI（Python 单文件，标准库）                                   │
│    ├─ ffmpeg / ffprobe / yt-dlp       预处理、抽帧、响度、导出      │
│    ├─ npx multiplane                 片头卡/参数卡/封面            │
│    ├─ crv                            抽帧看片、九宫格              │
│    └─ npx? ✗ 不是：直接 HTTP 调 :5180  时间线读写、素材导入、绑定   │
```

## 为什么必须装 D剪 引擎

`mf` 不自己剪时间线——它只会两件事：**调 ffmpeg 拼文件**、**调 HTTP 接口读写 D剪 的时间线**。

真正的剪辑内核是 D剪：

- 时间线是一份 JSON（schema v7：`meta / videoTracks / audioTracks / overlays / markers`），存在 `~/.djian/projects/<pid>/timeline.json`
- 渲染走 **Remotion 4.0.526 + React 18**，逐帧合成，所以字幕/动画/画中画是真的"烧"进画面
- 引擎是 Node 服务，默认 **5180**，由 `@djian/host-bridge` 在宿主进程里按需拉起（也支持 `mf dj up` 手动起）
- 写请求必须带 `X-Djian-Client` 头，否则 403 `CLIENT_HEADER_REQUIRED`

所以在面板里剪片、加字幕、加动画、导出，全都依赖引擎活着。引擎死了 `mf` 就只剩 ffmpeg 那部分能力。

## 各个引擎/工具的分工

| 工具 | 版本 | 谁调用 | 端口 | 产物 | 能替换吗 |
|---|---|---|---|---|---|
| D剪 引擎 | 上游 `e1b6130`（2.1.3）/ 包 0.2.0 | DSH host-bridge、`mf` | 5180 | 时间线 JSON、成片、导出队列 | **不能**，是核心 |
| Remotion | 4.0.526 | D剪 内部 | — | 逐帧渲染 | 随 D剪，不能单独换 |
| ffmpeg | 9.0.2 | `mf` 全流程 | — | 转码、抽帧、响度、封面 | 能（8.x 也行） |
| Multiplane | 0.3.13 + Chromium | `mf shot` / `mf cover` | — | 片头卡/参数卡/结尾引导/封面 mp4·png | 能（替代是手搓 ffmpeg drawtext，效果差） |
| crv | pip 装 venv | `mf watch` | — | 去重帧 + 九宫格 | 能（替代是 ffmpeg fps + tile） |
| GPU worker | 自建 | `mf asr/translate/tts/sep/sovits` | ssh | 文字稿、译稿、配音 wav、人声轨 | 能（本机 CPU 极慢） |

## 数据怎么流

```
源片 ──► mf new 建工程（~/媒体库/工程/<日期>-<名称>/）
     ──► mf dj import → 拷进 ~/.djian/projects/<pid>/assets/（单文件 ≤512MB，超了自动切段）
     ──► D剪 时间线（JSON）—— 人在面板里剪
     ──► Remotion 渲染 ──► 中间 mp4
     ──► mf export：loudnorm 到 -14 LUFS + 按平台画布缩放 + 命名校验 → ~/媒体库/成品/<品牌>/<工程>/<平台>/
     ──► mf qc：分辨率/时长/响度/峰值校验（不达标不出片）
```

**规则只有一份**：`~/获客平台/知识库/剪辑规范.md`，其中 §9 是一个 JSON 块（画布、时长、镜头长度、转场上限、字幕字号与留白、配乐音量、响度、编号规则、禁用词）。

- `mf` 每次运行都重新解析它（`rules()`），改完立刻生效，不用重启；
- D剪 的预设在获客项目里也被要求先读它（`djian-bundle/cordis.patch.yml` 的人设）。

## 两个补丁为什么要存在

| 补丁 | 文件 | 改了什么 |
|---|---|---|
| `djian-session-binding.patch` | `webui/server/store.mjs`、`routes.mjs`、`host-bridge/lib/engine-client.js` | 同名空项目复用而非新建；`POST /api/session-project` 支持 `{pid}` 显式绑定；`projectFor` 加 2 秒缓存 |
| `djian-desktop-shell.patch` | `webui/server/http.mjs`、`client-timeline` | 放行 `dsh-app://` origin；前端把 API 指回本机回环 |

补丁钉在上游 `e1b6130`。CI 的 `engine` job 会 clone 上游、checkout 这个 ref、打两个补丁、跑真 `store.mjs` 的 5 条测试；另有一条**不拦截**的漂移探测，在上游 HEAD 上失配只打 ⚠️——升级 D剪 前先看它。

## 已知边界（别踩）

1. **CI 的引擎测试用 stub** 顶替 `engine/dist/*`，验的是我们改的那段逻辑，不验渲染质量；
2. **D剪 人设没有硬拦截**，违规靠 `huoke_lint.py`（`mf dj check` / `mf export` 两道闸）和事后抽查；
3. **模板只有三类**（title / params / endcard），复杂片头要自己写 `shot.html`；
4. **合规闸只查时间线里的文字**，画面里拍到的电话号码、微信二维码它看不见，得靠人；
5. **Mac 上不做转录**：无 CUDA，whisper 走 CPU 会慢到没法用，一律走 Windows。
